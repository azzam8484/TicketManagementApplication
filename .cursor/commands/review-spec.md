# Review Spec

When this command is run, review or implement work from a specification.

## Steps

1. Locate the spec from the user path, or from `docs/`, `spec/`, or `.specstory/history/`
2. Read the full spec before changing code
3. Extract acceptance criteria as a short checklist
4. Map each criterion to touchpoints (endpoint, service, migration, UI)
5. Implement or review only what the spec requires
6. Mark each criterion as met, unmet, or blocked

## Constraints

- Do not add features outside the spec
- Follow existing project rules for implementation style
- If the spec is ambiguous, list questions before inventing behavior
