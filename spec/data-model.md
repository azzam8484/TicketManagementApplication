# Data Model

## Purpose of this document

This document defines the **MVP data model** for the Ticket Management System:

- entities
- fields and types
- required vs optional values
- relationships
- constraints
- indexing and persistence guidance

## 1. Overview

MVP persists **two entities only**:

1. **Ticket** — main work item (create, update, search, filter, status transition)
2. **Comment** — text note attached to a ticket

There is **no User entity** in MVP. Assignee is free text on the ticket (no login / user directory).

```text
Ticket (1) ────────< (N) Comment
```

- One ticket has zero or more comments
- Each comment belongs to exactly one ticket

## 2. Design choices (MVP)

| Choice | Decision | Reason |
|---|---|---|
| Primary keys | UUID | Matches API contract (`id` as UUID string) |
| Enum storage | String (`VARCHAR`) | Readable; safer than ordinal integers |
| Timestamps | UTC (`TIMESTAMPTZ`) | Consistent across environments |
| Assignee | Nullable string | Auth/users out of MVP scope |
| Comment author | Not stored | No auth in MVP |
| Soft delete | Not used | Terminal statuses cover end states |
| History/audit table | Not used | Not required for MVP |

## 3. Enumerations

### 3.1 TicketStatus

| Value | Description |
|---|---|
| `OPEN` | Initial status for every new ticket |
| `IN_PROGRESS` | Work has started |
| `RESOLVED` | Work finished; waiting to close |
| `CLOSED` | Terminal completed state |
| `CANCELLED` | Terminal cancelled state |

Rules:

- On create, `status` is always `OPEN`
- Allowed transitions are defined in `state-machine.md`
- `CLOSED` and `CANCELLED` have no further status changes

### 3.2 TicketPriority

| Value |
|---|
| `LOW` |
| `MEDIUM` |
| `HIGH` |

Rules:

- Required on create
- Must be exactly one of the values above when set

## 4. Entity: Ticket

### 4.1 Fields

| Field | DB column | Type | Required | Default | Description |
|---|---|---|---|---|---|
| `id` | `id` | UUID | yes | generated | Primary key |
| `title` | `title` | VARCHAR(200) | yes | — | Short summary |
| `description` | `description` | TEXT | yes | — | Full description |
| `status` | `status` | VARCHAR(32) | yes | `OPEN` | Current status |
| `priority` | `priority` | VARCHAR(16) | yes | — | Priority level |
| `assignee` | `assignee` | VARCHAR(100) | no | `NULL` | Free-text assignee |
| `createdAt` | `created_at` | TIMESTAMPTZ | yes | now (UTC) | Creation time |
| `updatedAt` | `updated_at` | TIMESTAMPTZ | yes | now (UTC) | Last ticket modification time |

### 4.2 Field rules

**`id`**
- Generated by application or database
- Immutable after insert
- Exposed to clients as UUID string

**`title`**
- Required
- Trim before save
- Must not be blank after trim
- Max length: 200

**`description`**
- Required
- Trim before save
- Must not be blank after trim
- Stored as TEXT
- Practical validation max: 10_000 characters

**`status`**
- Required
- Must be a valid `TicketStatus`
- Forced to `OPEN` on create
- Changed only via status-change logic (not via general field update)

**`priority`**
- Required
- Must be a valid `TicketPriority`

**`assignee`**
- Optional
- Trim if provided
- Empty string normalized to `NULL` (unassigned)
- Max length: 100

**`createdAt`**
- Set once on insert
- Never updated afterward

**`updatedAt`**
- Set on insert
- Updated when ticket fields or status change
- **Not** updated when only a comment is added

### 4.3 Ticket constraints

| Constraint | Definition |
|---|---|
| Primary key | `id` |
| Not null | `title`, `description`, `status`, `priority`, `created_at`, `updated_at` |
| Check (status) | `status IN ('OPEN','IN_PROGRESS','RESOLVED','CLOSED','CANCELLED')` |
| Check (priority) | `priority IN ('LOW','MEDIUM','HIGH')` |
| Length | `title` ≤ 200, `assignee` ≤ 100 |

### 4.4 Indexes (Ticket)

| Index | Columns | Purpose |
|---|---|---|
| PK | `id` | Point lookups |
| `idx_ticket_status` | `status` | Filter by status |
| `idx_ticket_created_at` | `created_at DESC` | Default list ordering |

Search note:

- MVP keyword search matches **title** and **description** (case-insensitive)
- Acceptable approach: `ILIKE` / case-insensitive `LIKE`
- Dedicated full-text indexes are optional (not required for MVP)

### 4.5 Table definition (logical SQL)

```sql
CREATE TABLE tickets (
  id            UUID PRIMARY KEY,
  title         VARCHAR(200)  NOT NULL,
  description   TEXT          NOT NULL,
  status        VARCHAR(32)   NOT NULL,
  priority      VARCHAR(16)   NOT NULL,
  assignee      VARCHAR(100)  NULL,
  created_at    TIMESTAMPTZ   NOT NULL,
  updated_at    TIMESTAMPTZ   NOT NULL,
  CONSTRAINT chk_ticket_status
    CHECK (status IN ('OPEN', 'IN_PROGRESS', 'RESOLVED', 'CLOSED', 'CANCELLED')),
  CONSTRAINT chk_ticket_priority
    CHECK (priority IN ('LOW', 'MEDIUM', 'HIGH'))
);

CREATE INDEX idx_ticket_status ON tickets(status);
CREATE INDEX idx_ticket_created_at ON tickets(created_at DESC);
```

## 5. Entity: Comment

### 5.1 Fields

| Field | DB column | Type | Required | Default | Description |
|---|---|---|---|---|---|
| `id` | `id` | UUID | yes | generated | Primary key |
| `ticketId` | `ticket_id` | UUID | yes | — | FK → `tickets.id` |
| `text` | `text` | TEXT | yes | — | Comment body |
| `createdAt` | `created_at` | TIMESTAMPTZ | yes | now (UTC) | Creation time |

### 5.2 Field rules

**`id`**
- Generated
- Immutable

**`ticketId`**
- Required
- Must reference an existing ticket
- Immutable after insert (comments are not moved between tickets)

**`text`**
- Required
- Trim before save
- Must not be blank after trim
- Practical validation max: 5_000 characters

**`createdAt`**
- Set on insert
- Immutable

### 5.3 Comment constraints

| Constraint | Definition |
|---|---|
| Primary key | `id` |
| Foreign key | `ticket_id` → `tickets.id` |
| Not null | `ticket_id`, `text`, `created_at` |

### 5.4 Referential action

| Situation | Behavior |
|---|---|
| Delete ticket | Not an MVP product operation |
| FK `ON DELETE` | `CASCADE` (recommended for DB integrity) |
| Update ticket `id` | Not allowed (`id` immutable) |

### 5.5 Indexes (Comment)

| Index | Columns | Purpose |
|---|---|---|
| PK | `id` | Point lookups |
| `idx_comment_ticket_id_created_at` | `ticket_id`, `created_at ASC` | Load comments for a ticket in order |

### 5.6 Table definition (logical SQL)

```sql
CREATE TABLE comments (
  id          UUID PRIMARY KEY,
  ticket_id   UUID          NOT NULL,
  text        TEXT          NOT NULL,
  created_at  TIMESTAMPTZ   NOT NULL,
  CONSTRAINT fk_comment_ticket
    FOREIGN KEY (ticket_id) REFERENCES tickets(id) ON DELETE CASCADE
);

CREATE INDEX idx_comment_ticket_id_created_at
  ON comments(ticket_id, created_at ASC);
```

## 6. Relationships

| Relationship | Type | Rule |
|---|---|---|
| Ticket → Comment | One-to-many | A ticket can have 0..N comments |
| Comment → Ticket | Many-to-one | Each comment belongs to exactly one ticket |

- Creating a comment for a missing ticket is invalid (not-found / integrity failure)
- Ticket detail loads comments ordered by `created_at` ascending

## 7. Data lifecycle by operation

| Operation | Ticket changes | Comment changes |
|---|---|---|
| Create ticket | Insert; `status=OPEN`; set timestamps | none |
| List / search / filter | Read-only | none |
| View ticket details | Read ticket | Read comments for `ticket_id` |
| Update fields | Update title/description/priority/assignee; bump `updated_at` | none |
| Change status | Update `status` if allowed; bump `updated_at` | none |
| Add comment | none | Insert comment row |

## 8. Validation rules tied to data

### Ticket create
- `title` non-blank
- `description` non-blank
- `priority` valid enum
- `assignee` optional
- `status` forced to `OPEN`

### Ticket field update
- Updatable: `title`, `description`, `priority`, `assignee` only
- Same non-blank/enum rules for provided fields
- `status` is not updated on this path

### Status change
- Target must be a valid `TicketStatus`
- Transition must be allowed per `state-machine.md` before write

### Comment create
- `ticketId` must exist
- `text` non-blank

## 11. Out of model for MVP

Do not add unless requirements change:

- `users` / `roles` / `permissions`
- assignee link tables
- attachments
- tags
- ticket history / audit events
- notifications
- soft-delete columns (`deleted_at`)
